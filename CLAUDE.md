# Still Water

A short procedural pixel-art fishing horror game in one self-contained HTML file, built for mobile portrait and itch.io.

The art style follows NakoFrish's "AM: The Verdant Reach" image: a blue fjord, big pixel cumulus with bright tops, a low white sun in the centre, a mirror-still lake, and a dark boat with curled prow and stern.

Premise: it starts as a calm fishing game, and a golden fish grants three wishes. Then the sun sets and a red eye-sun rises, hanging on a line from the sky. Every sun is bait, the mountains are teeth, and the player is the fish. There are seven endings (Home, Dark, Still water, Stay, Deep, Swallowed, Inside) and a silent variant of Still water. The script and the world-state ledger are `docs/story.md`; when the code and the bible disagree, fix one the same day. The game ships in English and Russian, one page per language (see Languages).

## Commands
- `npm install`: run once. It only installs the dev tools, pngjs and jsdom.
- `npm run build`: writes `dist/index.html` by inlining `src/game.js` into `src/template.html` at `/*GAME*/`. Full-line `//` comments are dropped on the way (the source keeps them) to keep the single file small (about 145 KB; itch.io has no practical limit at this size, so this is a tidiness target, not a hard cap). Never edit `dist/` by hand.
- `npm run sim`: a headless bot plays through every ending (plans are choice indices in menu order, listed at the top of `tools/sim.js`; a `{ wait: true }` option holds the bot through the ocean window, `{ tap: true }` taps the companion once per act, a third element is a sentence the ending card must end with, `{ base: n }` the bible's situation number whose exact text the card must start with, `{ noPocket: true }` for the lake-sunk Still water card, `{ ruCard: { base, extra } }` the Russian base and extra an Inside card must carry in the Russian pass). On every let-go plan it also asserts that `WS.goldKept` stays 0 through the dialogue, so `drawKeptFish` never stamps a kept fish on a released path. It prints one `ending <id> reached` line per ending id (the seven plus `cut:silent`). Then a Russian pass plays every plan again with `LANG` = 'ru' (`setLang`): each must reach the same ending as in English, and no text the player sees (every stub UI log entry of kind caption, think, dialogue, choices, card, ending, prompt and the panel label) may contain a Latin letter; it prints `ru ending <id> reached` lines and `RUSSIAN OK`. The English pass keeps all its assertions. The run must end with `ALL ENDINGS REACHED`. Its reel bot sees the line 0.35 s late, like a person (it lets go when it sees a surge or high tension), and each run's line carries `snaps=`; the summary line gives the snaps per run and the mean run length.
- `npm run shots`: renders scene states (`tools/shot.js`, one `out_*.png` per scene, `node tools/shot.js <scene>` for one) and ending frames (`tools/snaps.js`, `e_*.png`; each capture is timed from the wish 3 choice, or from the red rise with a third element `'red'`, or from the ending cinematic's start with `'cine'`) to `tools/out/`. Look at them after any visual change.
- `node tools/cloudshots.js`: renders the sky alone to `tools/out/clouds_*.png` (day at t 0 and 40 s, night, red, and the wrap seam at 20, 60 and 133 s) and times `render()` 300 times. Use it when touching the clouds.
- `npm run domtest`: plays the built page in jsdom with the canvas stubbed, then the Russian page (`tools/out/ru/index.html`, opened at its Pages address): its title, the link back to `../`, and one run with no Latin letter on screen. It is slow and takes a few minutes.
- `npm run skipcheck`: verifies the temporary test mode below: a skip is a no-op with test mode off and before the boat arrives, four skips reach the golden dialogue, a skipped run reaches the red sequence and an ending, and a skip in the ocean window casts into the big one. It takes under a second.
- `npm run build:test`: writes `tools/out/test.html`, a copy of the game with test mode already on. Publish that file when someone needs to play through the story on a phone without fishing. It is gitignored and must never be uploaded to itch.io.
- `node build.js --lang=ru` (combinable with `--test`; `npm run build:ru` runs both): the Russian page, `tools/out/ru/index.html` and `tools/out/ru/test.html` (gitignored). `--out=<path>` writes anywhere else; `npm run build:site` builds the four published pages into `site/` (gitignored) exactly as the Pages workflow does, so the language links can be tried locally over HTTP.

## Test mode (test build only)
Skips the fishing minigame so the story can be reached in seconds. It exists only in the test build (`npm run build:test`, `tools/out/test.html`): `const TEST_BUILD = false;` in `src/game.js` gates the T and S keys, the Skip fish button and the `?test` flag in the browser, and `build.js --test` flips it. The shipping `dist/index.html` has no test mode. In the test build, open it with `?test` (or `#test`), or press T to toggle it. A dashed "Skip fish" button appears in the HUD; each click (or the S key) lands the next fish as if it had been reeled in, including the golden fish and the act 2 red sequence. Dialogue and cinematics still play normally. It lives in `setTestMode` and `testCatch` in `src/game.js`, next to `release()`, and is exported to `tools/`, where the Node tools call it directly.

## Languages (i18n)
One page per language: the language is set by which page you open, never by the browser or a saved choice. `const DEFAULT_LANG = 'en';` in `src/game.js` is baked in by the build (`build.js --lang=ru` flips it, the way `--test` flips `TEST_BUILD`; the plain build stays English), and `pickLang` lets `?lang=ru` or `?lang=en` override it for testing. There is no localStorage language and no `navigator.language`. The four published pages (`.github/workflows/pages.yml`): `/` (English), `/test.html` (English test build), `/ru/` (`--lang=ru`), `/ru/test.html` (`--lang=ru --test`). On the title a small link next to Mute (`#lang`, the same 44 px frame, hidden once play starts) names the other language (RU on the English page, EN on the Russian one) and goes to its page: `langHref` sends the English page down to `ru/` (or `ru/test.html` from `test.html`) and the Russian page up to `../` (or `../test.html`), relative to `location.pathname`, so it works under `/still-water/` on Pages; under `file://` it names `index.html`, and with a `?lang` override it links to `?lang=<other>` on the same page.

The mechanism: `RU` (in the language section after `RECOUNT`) is keyed by the exact English string, and `tr(s)` returns the Russian in RU mode and `s` otherwise. Text is translated where it reaches the player: `cap` (every caption), `thinkLine` and `dlgBubble` (the bubbles and the Fisherman label), `dlgRun` (each line copied through `trLine`: text and choice labels; `who` stays English because `fishSpeaking` compares it, and `dlgNext` translates it for the panel), `lakeWhisper`, `showCard` (`cardView`: name, line, voice and `kgText`, a decimal comma in Russian), `composeEnding`, `refreshPrompt` (the urgent style compares against `tr('Tap now')`), the HUD (`countText`, with Russian plurals from `ruPlural`), the found counters (`foundText`), the found list and its aria labels, the Mute label, and the template's own text, which `staticText` sets at boot from `STATIC_TEXT` (with `<html lang>` and the tab title; `build.js` also writes both into the page for link previews). Logic never reads translated text: choices pick by closure. Composed text translates its parts before joining: `trJoin` (the sunset caption with `placeWord`, the wish 2 cost line), `recountLine` (each clause through `sentence(tr(...))`), `askedLine` (header and labels), `endingBase` (an `END_BASES` cell built from shared pieces is an array of parts, e.g. `[KNOW_WAY, 'bring', NEW_SHORE]`), `endingExtra`, and `stayBase` (strips `' ' + tr(STAY_DARK)`). The Russian is a literary translation (the golden fish speaks in the feminine, and her question is «Чего тебе надобно, рыбак?»); it was drafted as a table of ids with notes and reviewed, and only the text ships, as `RU`.

To add a string: write it in English where it is used (whole sentences, never an English phrase spliced into another), add `'English': 'Russian'` to `RU`, and make sure it reaches the player through one of the paths above (a new UI text sink must call `tr`). If it is composed, give each piece its own entry and join the translated pieces. Keep English unchanged when you add Russian. `npm run sim` fails if any text the player would see in Russian holds a Latin letter.

## Rules
- The game stays a single HTML file, with no image or audio assets. All art is procedural and all sound is synthesised with WebAudio. The only external request is one Google Fonts stylesheet for two families, Literata (400 to 500 with the optical-size axis, and italic 400) and Press Start 2P (400), with display=swap and real fallbacks (PT Serif, Georgia, serif; ui-monospace, monospace); the Latin and Cyrillic subsets load by unicode-range.
- Everything is palette-indexed. Add colours as palette indices, never as raw RGB in the render path, so they recolour with the mood.
- Design for mobile first: portrait layout and tap/hold controls. Keep per-pixel work cheap, because `renderTop` and `computeWater` run every frame.
- UI copy is sentence case, short and eerie, in both languages. Every string the player sees has a Russian entry in `RU`.

## Architecture (src/game.js)
The internal resolution is 216 wide by H tall. H ranges from 384 to 470, chosen from the screen aspect, and the image is upscaled with nearest-neighbour. The horizon row is `HY = 236` and the boat waterline is `WL = HY + 6`.

Palette: `buildPalette(mood, dim)` fills `PAL` (RGBA) and `PALRGB`.
- 0–11: the main ramp, blended day, then night, then blood as `WS.mood` goes 0, 1, 2. `dim` darkens it for the Dark ending.
- 12 bobber, 13–16 gold, 17 lantern, 18 fish eye, 19 black, 20 star, 21 red eyes, 22–23 bone, 24 eye glint (the dimmer pair under each pair of eyes), 25 the new shore's dark green (`SHORE_GREEN`). Each mood's values are in `ACC`.
- Sprite strings map characters to indices through `CH`: `0-9 a b` for the ramp, `R d g y w L E K S X` for accents, and `.` for transparent.
- `dith(f, x, y)` turns a continuous shade into an index, using Bayer dithering only near band edges.

Buffers:
- `MOUNT` is generated once in `init`. `CLOUDS` holds two cloud layers (the near cumulus at 3 px/s and the far wisps by the horizon at 1.1 px/s), each a strip `CW = 2W` wide that wraps. `CUMULUS` lists each cloud (layer, centre, flat base, size, bumps); `makeCumulus` builds it as a union of circles with a lifted top row, `cloudField` takes the signed distance to the silhouette (roughened by tiled noise so the strip wraps) and `shadeCloud` lights it: a 2 to 4 px band of index 11 along the upper contour facing the sun, a softer band under it, a mid body, a flat dark base, Bayer dither only at tone edges. `renderTop` samples the layers with a per-layer offset from `cloudT` (which stops while `WS.frozen`), and `KCOR` cuts the fixed sun corridor at sample time so it never drifts with them. Phase 26: `cloudView` (per frame, from `cloudTick`) builds per-layer tables, a source column per screen column (`L.xs`, drift folded in) and a source row base and tile shift per row (`L.rb`, `L.rd`), scaled by 1 / s about (SUNX, HY) with s = lerp(1, `CLOUD_FAR_S` 0.5, `WS.far`), so the clouds shrink with the camera; rows above the strip tile it upward with the period `L.band` (`cloudBand`) and `CLOUD_TILE_DX` per tile (the wisps do not tile); `cloudIdx` reads the same tables. 0.5 keeps the scaled strip within one wrap, so no cloud shows twice in a row. `out_zoom_clouds_strip.png` shows it.
- `TOP` holds the sky, sun, clouds and mountains above the horizon.
- `FRAME` is `TOP` plus the mirrored water.
- `SPR` holds sprites, with 255 meaning transparent.
- `IDX` holds the final indices, and `OUT32` is the RGBA written to the canvas.

Frame order in `render(t)`:
1. Palette.
2. `renderTop`.
3. `topExtras`: stars, birds, cabin and the stalk line.
4. `computeWater`: the mirror with per-row ripple `RIPX`, plus glints.
5. Rings, fish shadows and the eyes (`drawEyes`, in the water, never reflected).
6. Sprites with reflections, via `plotR` and `stampR`.
7. `composite`, which includes the jaw shift.
8. `drawFangs`.
9. `drawUIPix`: the bite marker and the tension bar (`drawTensionBar`: 5 px of fill, the snap zone past `BAR_DANGER` 0.78 shaded index 24 all the time, no tick).
10. RGBA conversion.
11. `applyGlows`: lantern and cabin light.

State:
- `WS` holds the world and mood. Each visual beat is a numeric field, such as `mood`, `sunY`, `sunKind`, `pupil`, `stalk`, `jaw`, `lantern`, `ash`, `companion`, `cabin` (the building; `cabinLit` is its window light, 0 after the still-water dawn, when `CABIN_DARK` is stamped and the glow is off) and `gold`. Animate them with `tween(obj, key, to, dur, ease, done)`; `untween` cancels one. `zoomAnchorX` glides the group’s centre to the horizon centre on the same eased `far`; `farRings` sends a dark `ring` (its `dark` flag shades down, so it reads on the glare) from the waterline every `FAR_RING_GAP` 1.2 s while `far > 0`; `farLive` gates the line and the lantern glow; birds and the sky fish hidden past 0.5; `out_zoom_strip.png` and `out_zoom_swim_strip.png` are eight frames across the pull-back; phase 22: the shoal fades in already in the water (`SHOAL_FADE_IN`) and swims alone after the pull-back; The C key taps the companion when `companionOpen`. The eyes' positions come from `mulberry32(RUN.count + 7)`, so shots are deterministic.
- `G` is the fishing state machine. Its phases are title, ready, casting, waiting, bite, reeling, landing, card, lost, dialog, cine, ocean (the cast-or-wait window) and end. The only inputs are `press()` and `release()`.
- `STORY` holds the act (0–2), catches, `wishes` (granted wishes only, in order), `heard`, `goldenNext`, and the bible's flags: `kept`, `firstAsk` ('company' | 'fish' | 'home' | 'nothing'), `refused` (0–2), `answered` (null | true | false), `ocean` ('none' | 'waited' | 'swallowed'), `said` (how many of the fisherman's three lines have shown), `usedRepl` (keys of the card replacements that have fired this run). Also `casts` (for the opening captions), `shown1` (species whose act 1 card was shown, so act 2 picks another), `keptNext` (kept, act 1: the next normal card closes into golden scene 2), `tap` and `tapPool` (the companion's line position and pool), `actCatches` and `lastSpecies`. `freshStory()` is the reset shape.
- `RUN` holds `count` (completed runs, from localStorage `stillwater-runs` plus this session) and `last` (the last ending id, `stillwater-last`; the silent variant is stored as `cut:silent`, so only a real cut gets the fish's `You cut the line last time.` line). `isLaterRun()` gates the second-run lines. It is reloaded in `resetAll`, and `showEnding` bumps it.

Fishing loop:
- Cast, then nibbles, then a bite after `BITE_WAIT` (1.2 s) plus up to `BITE_WAIT_RND` (2.4 s). The bite window is `BITE_WIN` 1.2 s (`FIRST_BITE_WIN` 1.6 s while `G.tutorial < 1`), or 3.2 s for the golden fish. The bite prompt is 'Tap now'. The act 2 golden cast has no bite at all: when its bite time comes, `fishUpdate` starts `redSequence` (no `Tap now`, no way to miss it).
- Hold to reel. Progress rises at `REEL_RATE` (0.42) divided by the species' weight `d`. Tension `reel.T` rises at `PULL_BASE` (0.32), plus `PULL_SURGE` (1.0) during a surge, times `d`, and falls at `RELEASE_EASE` (0.95) on release; surges come every `SURGE_GAP` (1.2 s) plus up to `SURGE_GAP_RND` (1.8 s). These were eased on 2026-09-30 so first-time players land fish faster; with the sim's 0.35 s reaction bot no line snaps and a run averages about 2.4 minutes. The line snaps at 1. A surge is cued (ring, sound, jitter) `SURGE_WARN` (0.25 s) before it pulls: `reel.sAge` counts from its start and the surge term applies only past the warning, so a person can react. Letting go costs `RELEASE_LOSS` (0.06) of progress a second. The golden fish reels at `GOLD_REEL_D` 1.0 under `GOLD_T_CAP` 0.62, so it is heavy but cannot snap, and it lands with no reel-end splash (it surfaces at the left with its own), its reflection calm (`stampR`'s `calm`: whole rows with every `CALM_GAP` 3rd row left out, each shifted by its ripple, one step down the gold ramp by `reflCalm`). The first snap of a run says 'The line snapped. Let go when it pulls.' (`STORY.snaps`).
- When progress `reel.p` reaches 1 the fish lands and a card appears. The card ignores taps for `CARD_GRACE` (0.5 s), and its "Tap to continue" hint fades in after that. `pickSpecies` never repeats a species whose card already showed this act (`STORY.actSeen`, reset in `startAct`) unless nothing else is left.
- Species are in `SPECIES` and per-act descriptions are in `DESC`. Each species carries its own palette (bible, section 5, 'How the fish look'): `pal` for acts 0 and 1 and a greyer, darker `pal2` for the act 2 name, with the marks `bar` (the perch's bars), `spot`, `heart` (the perch's one red-brown pixel, `fishMarks`) and `tooth` (the grinning smelt's three bone pixels along the lower lip from act 1). `fishOpts(sp, act, seed)` builds the `makeFish` options (no eye on the eyeless perch, no spots on the hollow char since `pal2` has none). The ramp has no green or grey, so the trout and eel use the brown accents 13 and 14 for olive and the perch and grayling the bone pair 22–23. The golden fish keeps `GPAL`. The card canvas scale is `cardFishScale`: the largest integer factor (2 to 8) that keeps the sprite inside 60% of the card's width and 26% of the stage's width tall. `node tools/shot.js cards` renders `out_cards.png` (six rows, three acts) and `fish_<id>_<act>.png` at 6x.

Story (the script is `docs/story.md`; phase 1 of its build plan is in, text and state only, copy verbatim from the bible):
- Captions go through `cap(text, dur, style)`, which tracks the end time in `G.capUntil`. The fisherman's four act 0 lines are thought bubbles (`thinkBeat`, `thinkLine`): when the row-in arrives, `openingLine` shows the narrator's 'Nothing on the lake is moving except you.' ## Known issues
- Home ending: the jaw composite leaves a horizontal seam mid-screen, which the darkening and fangs mostly hide.
- Upscaling isn't an integer multiple on some screens, so pixel sizes are slightly uneven.
- The keyboard controls (Space/Enter, and 1–6 for choices) are only lightly tested; `domtest` drives one plan through them.
- The build's comment stripping is line-based: a full-line `//` inside a multi-line string or template literal would be dropped. `src/game.js` has none; keep it that way.
- Runtime: the longest path (keep, company, gold, answered, Cut) measures about 3 min 50 s with realistic tap pacing, well under the bible's seven-minute budget; the fishing minigame is most of it and varies by a few tens of seconds with the bite timers.
