# Still Water

A short procedural pixel-art fishing horror game in one self-contained HTML file, built for mobile portrait and itch.io.

The art style follows NakoFrish's "AM: The Verdant Reach" image: a blue fjord, big pixel cumulus with bright tops, a low white sun in the centre, a mirror-still lake, and a dark boat with curled prow and stern.

Premise: it starts as a calm fishing game, and a golden fish grants three wishes. Then the sun sets and a red eye-sun rises, hanging on a line from the sky. Every sun is bait, the mountains are teeth, and the player is the fish. There are six endings (Home, Dark, Still water, Stay, Deep, Swallowed) and a silent variant of Still water. The script and the world-state ledger are `docs/story.md`; when the code and the bible disagree, fix one the same day.

## Commands
- `npm install`: run once. It only installs the dev tools, pngjs and jsdom.
- `npm run build`: writes `dist/index.html` by inlining `src/game.js` into `src/template.html` at `/*GAME*/`. Full-line `//` comments are dropped on the way (the source keeps them) to keep the single file small (about 145 KB; itch.io has no practical limit at this size, so this is a tidiness target, not a hard cap). Never edit `dist/` by hand.
- `npm run sim`: a headless bot plays through every ending (plans are choice indices in menu order, listed at the top of `tools/sim.js`; a `{ wait: true }` option holds the bot through the ocean window, `{ tap: true }` taps the companion once per act, a third element is a sentence the ending card must end with, `{ base: n }` the bible's situation number whose exact text the card must start with, `{ noPocket: true }` for the lake-sunk Still water card). On every let-go plan it also asserts that `WS.goldKept` stays 0 through the dialogue, so `drawKeptFish` never stamps a kept fish on a released path. It prints one `ending <id> reached` line per ending id (the six plus `cut:silent`) and must end with `ALL ENDINGS REACHED`. Its reel bot sees the line 0.35 s late, like a person (it lets go when it sees a surge or high tension), and each run's line carries `snaps=`; the summary line gives the snaps per run and the mean run length.
- `npm run shots`: renders scene states (`tools/shot.js`, one `out_*.png` per scene, `node tools/shot.js <scene>` for one) and ending frames (`tools/snaps.js`, `e_*.png`; each capture is timed from the wish 3 choice, or from the red rise with a third element `'red'`, or from the ending cinematic's start with `'cine'`) to `tools/out/`. Look at them after any visual change.
- `node tools/cloudshots.js`: renders the sky alone to `tools/out/clouds_*.png` (day at t 0 and 40 s, night, red, and the wrap seam at 20, 60 and 133 s) and times `render()` 300 times. Use it when touching the clouds.
- `npm run domtest`: plays the built page in jsdom with the canvas stubbed. It is slow and takes a few minutes.
- `npm run skipcheck`: verifies the temporary test mode below: a skip is a no-op with test mode off and before the boat arrives, four skips reach the golden dialogue, a skipped run reaches the red sequence and an ending, and a skip in the ocean window casts into the big one. It takes under a second.
- `npm run build:test`: writes `tools/out/test.html`, a copy of the game with test mode already on. Publish that file when someone needs to play through the story on a phone without fishing. It is gitignored and must never be uploaded to itch.io.

## Test mode (test build only)
Skips the fishing minigame so the story can be reached in seconds. It exists only in the test build (`npm run build:test`, `tools/out/test.html`): `const TEST_BUILD = false;` in `src/game.js` gates the T and S keys, the Skip fish button and the `?test` flag in the browser, and `build.js --test` flips it. The shipping `dist/index.html` has no test mode. In the test build, open it with `?test` (or `#test`), or press T to toggle it. A dashed "Skip fish" button appears in the HUD; each click (or the S key) lands the next fish as if it had been reeled in, including the golden fish and the act 2 red sequence. Dialogue and cinematics still play normally. It lives in `setTestMode` and `testCatch` in `src/game.js`, next to `release()`, and is exported to `tools/`, where the Node tools call it directly.

## Rules
- The game stays a single HTML file, with no image or audio assets. All art is procedural and all sound is synthesised with WebAudio. The only external request is the Pixelify Sans Google Font, which has fallbacks.
- Everything is palette-indexed. Add colours as palette indices, never as raw RGB in the render path, so they recolour with the mood.
- Design for mobile first: portrait layout and tap/hold controls. Keep per-pixel work cheap, because `renderTop` and `computeWater` run every frame.
- UI copy is sentence case, short and eerie.

## Architecture (src/game.js)
The internal resolution is 216 wide by H tall. H ranges from 384 to 470, chosen from the screen aspect, and the image is upscaled with nearest-neighbour. The horizon row is `HY = 236` and the boat waterline is `WL = HY + 6`.

Palette: `buildPalette(mood, dim)` fills `PAL` (RGBA) and `PALRGB`.
- 0–11: the main ramp, blended day, then night, then blood as `WS.mood` goes 0, 1, 2. `dim` darkens it for the Dark ending.
- 12 bobber, 13–16 gold, 17 lantern, 18 fish eye, 19 black, 20 star, 21 red eyes, 22–23 bone, 24 eye glint (the dimmer pair under each pair of eyes), 25 the new shore's dark green (`SHORE_GREEN`). Each mood's values are in `ACC`.
- Sprite strings map characters to indices through `CH`: `0-9 a b` for the ramp, `R d g y w L E K S X` for accents, and `.` for transparent.
- `dith(f, x, y)` turns a continuous shade into an index, using Bayer dithering only near band edges.

Buffers:
- `MOUNT` is generated once in `init`. `CLOUDS` holds two cloud layers (the near cumulus at 3 px/s and the far wisps by the horizon at 1.1 px/s), each a strip `CW = 2W` wide that wraps. `CUMULUS` lists each cloud (layer, centre, flat base, size, bumps); `makeCumulus` builds it as a union of circles with a lifted top row, `cloudField` takes the signed distance to the silhouette (roughened by tiled noise so the strip wraps) and `shadeCloud` lights it: a 2 to 4 px band of index 11 along the upper contour facing the sun, a softer band under it, a mid body, a flat dark base, Bayer dither only at tone edges. `renderTop` samples the layers with a per-layer offset from `cloudT` (which stops while `WS.frozen`), and `KCOR` cuts the fixed sun corridor at sample time so it never drifts with them.
- `TOP` holds the sky, sun, clouds and mountains above the horizon.
- `FRAME` is `TOP` plus the mirrored water.
- `SPR` holds sprites, with 255 meaning transparent.
- `IDX` holds the final indices, and `OUT32` is the RGBA written to the canvas.

Frame order in `render(t)`:
1. Palette.
2. `renderTop`.
3. `topExtras`: stars, birds, cabin and the stalk line.
4. `computeWater`: the mirror with per-row ripple `RIPX`, plus glints.
5. Rings, fish shadows and the eyes (`drawEyes`, in the water, never reflected).
6. Sprites with reflections, via `plotR` and `stampR`.
7. `composite`, which includes the jaw shift.
8. `drawFangs`.
9. `drawUIPix`: the bite marker and the tension bar (`drawTensionBar`: 5 px of fill, the snap zone past `BAR_DANGER` 0.78 shaded index 24 all the time, no tick).
10. RGBA conversion.
11. `applyGlows`: lantern and cabin light.

The C key taps the companion when `companionOpen`. The eyes' positions come from `mulberry32(RUN.count + 7)`, so shots are deterministic.
- `G` is the fishing state machine. Its phases are title, ready, casting, waiting, bite, reeling, landing, card, lost, dialog, cine, ocean (the cast-or-wait window) and end. The only inputs are `press()` and `release()`.
- `STORY` holds the act (0–2), catches, `wishes` (granted wishes only, in order), `heard`, `goldenNext`, and the bible's flags: `kept`, `firstAsk` ('company' | 'fish' | 'home' | 'nothing'), `refused` (0–2), `answered` (null | true | false), `ocean` ('none' | 'waited' | 'swallowed'), `said` (how many of the fisherman's three lines have shown), `usedRepl` (keys of the card replacements that have fired this run). Also `casts` (for the opening captions), `shown1` (species whose act 1 card was shown, so act 2 picks another), `keptNext` (kept, act 1: the next normal card closes into golden scene 2), `tap` and `tapPool` (the companion's line position and pool), `actCatches` and `lastSpecies`. `freshStory()` is the reset shape.
- `RUN` holds `count` (completed runs, from localStorage `stillwater-runs` plus this session) and `last` (the last ending id, `stillwater-last`; the silent variant is stored as `cut:silent`, so only a real cut gets the fish's `You cut the line last time.` line). `isLaterRun()` gates the second-run lines. It is reloaded in `resetAll`, and `showEnding` bumps it.

Fishing loop:
- Cast, then nibbles, then a bite after `BITE_WAIT` (1.2 s) plus up to `BITE_WAIT_RND` (2.4 s). The bite window is `BITE_WIN` 1.2 s (`FIRST_BITE_WIN` 1.6 s while `G.tutorial < 1`), or 3.2 s for the golden fish. The bite prompt is 'Tap now'. The act 2 golden cast has no bite at all: when its bite time comes, `fishUpdate` starts `redSequence` (no `Tap now`, no way to miss it).
- Hold to reel. Progress rises at `REEL_RATE` (0.42) divided by the species' weight `d`. Tension `reel.T` rises at `PULL_BASE` (0.32), plus `PULL_SURGE` (1.0) during a surge, times `d`, and falls at `RELEASE_EASE` (0.95) on release; surges come every `SURGE_GAP` (1.2 s) plus up to `SURGE_GAP_RND` (1.8 s). These were eased on 2026-09-30 so first-time players land fish faster; with the sim's 0.35 s reaction bot no line snaps and a run averages about 2.4 minutes. The line snaps at 1. A surge is cued (ring, sound, jitter) `SURGE_WARN` (0.25 s) before it pulls: `reel.sAge` counts from its start and the surge term applies only past the warning, so a person can react. Letting go costs `RELEASE_LOSS` (0.06) of progress a second. The golden fish reels at `GOLD_REEL_D` 1.0 under `GOLD_T_CAP` 0.62, so it is heavy but cannot snap, and it lands with no reel-end splash (it surfaces at the left with its own), its reflection dithered to `GOLD_REFL_A` 0.4 (`stampR`'s `ra`). The first snap of a run says 'The line snapped. Let go when it pulls.' (`STORY.snaps`).
- When progress `reel.p` reaches 1 the fish lands and a card appears. The card ignores taps for `CARD_GRACE` (0.5 s), and its "Tap to continue" hint fades in after that. `pickSpecies` never repeats a species whose card already showed this act (`STORY.actSeen`, reset in `startAct`) unless nothing else is left.
- Species are in `SPECIES` and per-act descriptions are in `DESC`. Each species carries its own palette (bible, section 5, 'How the fish look'): `pal` for acts 0 and 1 and a greyer, darker `pal2` for the act 2 name, with the marks `bar` (the perch's bars), `spot`, `heart` (the perch's one red-brown pixel, `fishMarks`) and `tooth` (the grinning smelt's three bone pixels along the lower lip from act 1). `fishOpts(sp, act, seed)` builds the `makeFish` options (no eye on the eyeless perch, no spots on the hollow char since `pal2` has none). The ramp has no green or grey, so the trout and eel use the brown accents 13 and 14 for olive and the perch and grayling the bone pair 22–23. The golden fish keeps `GPAL`. The card canvas scale is `cardFishScale`: the largest integer factor (2 to 8) that keeps the sprite inside 60% of the card's width and 26% of the stage's width tall. `node tools/shot.js cards` renders `out_cards.png` (six rows, three acts) and `fish_<id>_<act>.png` at 6x.

- Phase 21, the Still water pictures: `cutCine(silent)` picks a variant with `cutVariant` (the composer's state) and moves the world through `CUT_MOVE` from the dawn beat: `row` (lake boat, Silent), `shore` (sea, heard: `gatherShoal` turns the sea shoal into `LEAD_N` shapes steered by `steerLead` to `leadSlot`s right of and below the boat; `WS.newShore` raises `NEWSHORE`, generated once by `genNewShore` and blended into `TOP` by `drawNewShore`), `speck` (sea, not heard or sunk: `WS.far` 0 to 1, then `WS.farDrift`; a sunk run uses `SWIM_FAR2`, `SWIM_FAR4` and `SWIM_SPECK`), `loop` (lake, sunk: swims ashore, black, back at his spot with `WS.goldBelow`, `drawGoldBelow`). `CUT_DUR` is each variant's length. The lantern's glow is off while `far > 0.5`. Snaps: `e_cut_gather`, `e_cut_newshore`, `e_cut_pull`, `e_cut_speck`, `e_cut_swimpull`, `e_cut_swimspeck`, `e_cut_loop_shore`, `e_cut_loop_back`.
- Cards: `cardLine` applies the bible's conditional replacements over `DESC`: one per card, first match wins, each at most once per run through `once(key, text)` and `STORY.usedRepl`; after the later-run 'lip' line `pickSpecies` excludes the perch in act 1. `VOICE` is keyed to `STORY.firstAsk` on the act 2 card when heard.

Dialogue: `dlgRun(lines, done)`. A line is `{who, text, style, choices, mark, bubble}`, `{act: fn}` or `{pause: seconds}`. The styles are '', 'narr', 'whisper' and 'red'. Choices are `{label, pick}`; a choice whose `pick` does not start a new `dlgRun` lets the list continue, so choices can sit mid-scene. Every tapped choice (`choiceList`) closes the panel (or the bubble) and runs `pick` at once; the label is never echoed in the fisherman's bubble (bible, 4b: a choice is already his line), and the sim asserts that no bubble text equals a label from any menu it saw. A `bubble` line (`comp(text)`, the companion's) shows complete in the bubble instead of the panel (`dlgBubble`) with the ▾ marker and stays until a tap (`dlgTap`), never on a timer; with choices ('Will you stay?') the buttons sit under the bubble and wait. No bubble is on a timer. `mark` flips the trailing question mark. `UI.caption(text, dur, style)` accepts 'whisper'; call it through `cap`. The dialogue panel is capped (`UI.dlgCap`, the `--dlg-max` variable set in `resize`) at 46% of the stage or the stage below the companion's head less the panel's bottom margin, whichever is smaller, with the question scrolling while buttons show (`#dialog.choosing`), so the panel never covers the companion; when four or more buttons still do not fit, `fitChoices` sets them in two columns (`#choices.grid`). A tap inside the panel never reaches `companionHit` (`UI.inDialog`). Every button is at least 44 CSS px tall. New buttons are cold for `CHOICE_GRACE` (0.4 s of game time, the `cold` class plus a check in the click handler and the digit keys), so the second tap of a double tap cannot pick a wish. The ocean window ignores taps for its first `OCEAN_GRACE` (1 s), then shows `Tap to cast` (`OCEAN.hint`, `promptFor`) and `drawOceanMarker` pulses a pale ring at `oceanMark()`, where the float lands; `OCEAN_RETURN` is 2.5 s. `Cast again` stays disabled and out of the tab order until `AGAIN_DELAY` (1.6 s) after the ending card appears.

Cinematics: `playCine(def, done)`, where `def = {dur, init(s), update(t, dt, at, s)}` and `at(key, time, fn)` fires once.

Audio: `SFX` synthesises every sound. The audio context is created and unlocked on the first user gesture. `SFX.weight(on)` is the big one's mass (bible, section 8): two sub-bass oscillators (44 and 52.5 Hz) through a 90 Hz low-pass plus a looped noise bed under 140 Hz, the gain ramping linearly from silence to `WEIGHT_VOL` over `OCEAN_CROSS` with no attack, held while it sits under the boat, and ramped out over `WEIGHT_OUT` (2 s) when it slides off (`CINE_OCEAN_BACK`), when `oceanCast` starts the Swallowed cinematic, and in `resetAll`. The `rumble` stinger stays only for the jaws.

UI: the DOM overlay lives in `src/template.html` and is wired up in `makeUI()`. `UI.colors()` pushes the live palette into CSS variables. The thought bubble (bible, 4b) is `#think`: `UI.think(text, {who, side, mark, choices, more})` shows it and `UI.thinkHide()` hides it; a panel line hides the bubble and a bubble line hides the panel. `more` lights `#thinkMore`, the same small ▾ 'more' marker as the panel's `#more`, inside the bubble's lower right, for every bubble that waits for a tap (his own lines, the companion's, the dialogue's bubble lines), which is every bubble. On `thinkLine` bubbles the ▾ lights only after `THINK_GRACE` (0.8 s), and a tap before that is ignored (`thinkCold`), so a reflex tap cannot dismiss one unread. The bubble keeps `pointer-events: none`, so the dismissing tap reaches the stage and `press`. Its outline is an inline SVG path from `cloudPath` (scalloped arcs, 1 px stroke in currentColor, near-transparent fill) plus two tail circles, laid out by `thinkLayout` from `THINK_AT` (internal pixels: the fisherman's bubble has its left edge at x 122 and bottom at y 186 with the tail leaving at x 150 toward his head; the companion's at x 100, y 190, or 172 with buttons, so the 44 px buttons clear his hat, tail at x 160 toward him), converted to stage percentages from the live stage width and `H`, width 40% of the stage, text at max(12px, 3.1u) (labels, the hint, the HUD and the title lines have a 10px floor); in the red (mood past 1) the companion's bubble uses `THINK_AT.companionRed` (bottom at y 205, right of the disc) so it never covers the eye (`thinkAnchor`) (about two thirds of the panel). `thinkRelayout` runs on resize. In Node, `stubUI()` replaces it (`think` logs a `['think', text, side]` entry, which the sim prints among the captions) and `module.exports` exposes the engine to `tools/`.

## Known issues
- Home ending: the jaw composite leaves a horizontal seam mid-screen, which the darkening and fangs mostly hide.
- Upscaling isn't an integer multiple on some screens, so pixel sizes are slightly uneven.
- The keyboard controls (Space/Enter, and 1–6 for choices) are only lightly tested; `domtest` drives one plan through them.
- The build's comment stripping is line-based: a full-line `//` inside a multi-line string or template literal would be dropped. `src/game.js` has none; keep it that way.
- Runtime: the longest path (keep, company, gold, answered, Cut) measures about 3 min 50 s with realistic tap pacing, well under the bible's seven-minute budget; the fishing minigame is most of it and varies by a few tens of seconds with the bite timers.
